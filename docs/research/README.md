# 技術調査・検証ドキュメント

本ディレクトリは [CONTRIBUTING.md](../../CONTRIBUTING.md) の開発フロー「3. リサーチ・技術検証」で
実施した調査・検証結果を**設計書類の一部として**管理する。

## 目的

- 未知の技術要素（新規ライブラリ・API仕様・ブラウザ互換性等）の調査結果を、口頭やチャットのみで終わらせず
  再利用可能な形で残す。
- [docs/basic-design.md](../basic-design.md)・[docs/detailed-design.md](../detailed-design.md) の
  設計判断の根拠（なぜその方式を採用したか）を追跡できるようにする。

## 配置・命名規則

- ファイル: `docs/research/<Issue番号>-<調査テーマ>.md`（例: `docs/research/42-copc-range-request.md`）
- 1調査テーマにつき1ファイル。Issueに対して複数の調査テーマがある場合はファイルを分ける。

## テンプレート

```markdown
# <調査テーマ>

- 関連Issue: #<番号>
- 調査日: YYYY-MM-DD

## 目的・背景

（何を明らかにするための調査か）

## 調査内容

（調べた方法・検証手順・試したコード等）

## 調査結果

（分かった事実。制約・数値・挙動など）

## 結論・採用方針

（この結果を受けて、設計・実装にどう反映するか。反映先の設計書セクションへのリンクを含める）

## 参考資料

（参照した公式ドキュメント・仕様・記事のURL等）
```

## 運用ルール

- 開発フロー「4. 設計」で設計書（basic-design.md / detailed-design.md）を更新する際は、
  対応する調査ドキュメントを「参考資料」または「関連文書」として相互参照する。
- 調査のみで設計変更に至らなかった場合も、判断根拠として本ディレクトリに残す。
